6. For the website migration, first verify the staged Site TXT records and custom-domain validation status after DNS is saved. After approval, save the two Google OAuth JavaScript origins. After reviewing the private Site audience, replace the editable apex A and `www` CNAME with the Site's targets; then verify TLS, landing, setup, Google sign-in, run links, and test Checkout return URLs on the new host. Make the public landing decision separately from this owner-private pilot. Change `SITE_ORIGIN` to the preferred host only after it works so result emails link there.

## Stop conditions

Stop the pilot and preserve the job/provider IDs for diagnosis if a reply names the wrong recipient, a duplicate send appears, two Macs claim the same thread, a run claims an unverified file change, a participant gains access without an owner grant, a signed event cannot be matched to its provider record, a queued reply becomes blocked because its source is missing, or the receipt calls provider acceptance inbox delivery. Do not retry an uncertain send until Resend's sent record and API logs settle whether it was accepted.

The browser's security-sensitive-access rule requires action-time confirmation for the pending GoDaddy DNS changes. The Resend development key and webhook were created after the user's confirmation. The TypeSafe development key was created after the user's request, then replaced and the earlier key deactivated.
