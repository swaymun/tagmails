# TagMails pricing model

Internal decision memo, checked October 3, 2026. These are current public list prices and illustrative calculations, not measured TagMails unit economics or a customer offer.

## What one charge buys

The billable unit should be **one accepted task turn**: one authorized inbound message that starts or resumes an agent run, plus its result email and retained receipt. A second substantive reply is another turn, including when an authorized participant sends it. A duplicate delivery, Gmail reaction, invalid `Model:` request, or rejected sender is not a billable turn. The account owner funds participant turns; the owner alone can grant participants. Show the expected debit before enabling a model route, and state the refund rule for failed or bounced replies before live payments.

The test wallet returns the five-cent reservation when the agent reports `failed`, `needs_approval`, or `needs_clarification`; its notice email still sends. For a completed run, it also returns the debit when Resend reports a terminal `bounced`, `failed`, or `suppressed` outcome for the reply's sole To recipient. That recipient is the sender of the task turn. A Cc recipient's failure alone does not release the charge, and a delayed event is not terminal. The release is one-way if a later event says delivered, in the customer's favor. This is an internal pilot rule; verify real provider event ordering and decide how to explain mixed-recipient outcomes before collecting money.

Keep two prices visibly separate:

1. **Bring your plan, subject to provider approval:** a possible service charge for intake, queueing, email reply, receipt, and seven-day file storage. This is not a customer offer. The owner-only Codex pilot uses the owner's sign-in; customer subscription use requires a supported commercial path or provider confirmation. Claude subscription use is excluded from the proposed beta.
2. **Managed API:** the same service charge plus measured model and tool spend and a disclosed management margin. Reserve a maximum before starting and return unused credit. This path is not implemented for customer billing.

## Illustrative math

The current **$0.05 test debit is a fixture price**, not a release price. If a $10 domestic-card top-up is fully consumed at five cents per turn, the $0.59 card fee allocates to about **$0.00295 per turn**, leaving **$0.04705** before mail, hosting, support, and refunds. At 100 turns/month, a standalone $5 Worker floor alone is $0.05/turn. At 1,000 turns/month it is $0.005/turn. One inbound and one result reply would consume about 2,000 Resend quota units; adding all three planned status reactions would submit up to 5,000 messages. If Resend counts those SMTP messages against the same quota, the Free plan's 3,000/month and 100/day caps could cover at most 600 fully reacted turns/month or 20/day. This needs verification against actual provider usage. If Pro is required, its $20 floor adds $0.02/turn at 1,000 turns. These are scenario divisions, not forecasts; shared Cloudflare costs and actual provider metering may differ.

The October 3 live 35-case routing evaluation passed all cases after fixing two unsupported-model fallbacks. It made 32 Jev calls using 35,147 input tokens, or about 1,098 per call. At the listed rate, that is an estimated **$0.00148 total** and **$0.000046 per classified email**; 1,000 similarly sized task emails would cost about **$0.046** in Jev input. This is list-price math from synthetic requests and reported token usage, not an invoice or a forecast for longer emails. The relay caps current subject and body text before classification. A reply without an explicit `Model:` line also calls Jev so natural requests can change models; if no change is clear, it keeps the thread route. Model, effort, speed, quoted-text, and unsupported-model examples passed in this corpus, but a larger and more varied corpus is needed before treating the observed accuracy as a customer error rate.

For comparison, 1,000 turns with a result email and all three status reactions would submit 4,000 outbound messages through Cloudflare Email Sending. At the listed allowance, the first 3,000 are included with Workers Paid and the next 1,000 cost about **$0.35**, plus the shared $5 Workers floor already counted above. This excludes rejected messages, deliverability losses, metadata/storage costs, and the work to replace Resend. The customer privacy gate also requires removing plaintext relay storage; the lower mail price alone does not make that design ready.

An illustrative API turn with **100,000 uncached input tokens and 5,000 output tokens** costs **$0.25** at the listed Sol or Sonnet rates, before extra tool, cache-write, long-context, and retry charges. A 10% model markup alone adds $0.025. After allocating the $10 top-up card fee proportionally, that markup contributes only about $0.009 before mail, hosting, support, and losses. The provisional five-cent service fee plus that API charge and 10% margin would total **$0.325** for this example, but a real agent turn can use many requests and cost much more. Do not publish a flat managed-model price without a hard budget and measured cost distribution.

The October 3 prompt evaluation saved usage for eight **active-prompt Codex Luna** turns on short synthetic email tasks. They reported 15,482–53,610 input tokens per turn, including 11,008–41,216 cached input tokens, and 49–184 output tokens. Applying the listed GPT-6.1 Sol rates to those token categories yields a **counterfactual** $0.0105–$0.0341 per turn, averaging $0.0188. These were subscription-backed Luna CLI runs, not Sol API charges; the small read-only fixtures omit production email delivery, files, retries, longer agent work, and any paid tools. The sample therefore cannot set a customer price. Even its average would leave only about 3.1 cents of a five-cent debit before payment fees, email, hosting, storage, and support if TagMails paid that model bill. [GPT-6.1 Sol list rates](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

## Proposed bring-your-plan beta offer

**Candidate for review, not enabled:** $0.15 per accepted task turn, a $10 minimum manual top-up credited in full, and no automatic reload. This price assumes a permitted bring-your-plan route and is blocked on provider terms. TagMails would charge for email intake, delivery, queueing, a private receipt, and the current seven-day file-transfer window. A substantive follow-up would cost another $0.15. Shared threads are deferred from the beta; do not price or sell participant turns yet. Duplicate mail, Gmail reactions, unsupported-model clarifications, and rejected senders would be free. Keep the current terminal-primary-recipient bounce release rule, but verify it with real Resend event order before publishing it. The current code still charges **$0.05 in Stripe test mode** and has no live billing path; this proposal does not change it.

This candidate is deliberately simple for customers, but it is not yet proven profitable. Assuming a $10 domestic-card top-up is fully spent, Stripe's $0.59 fee allocates to **$0.00885 per $0.15 turn**. The current synthetic 1,098-token Jev average adds about $0.000046. Allocating the full $5 Worker floor and, where shown, the full $20 Resend Pro floor gives:

| Monthly accepted turns | Resend plan | Fixed Worker + mail allocation/turn | Amount left from $0.15 after those floors, card fee, and estimated Jev |
| ---: | --- | ---: | ---: |
| 100 | Free, within both quotas | $0.050 | $0.091 |
| 100 | Pro | $0.250 | **−$0.109** |
| 200 | Pro | $0.125 | $0.016 |
| 1,000 | Pro | $0.025 | $0.116 |

These amounts exclude Site hosting, D1/R2 overages, support, taxes, disputes, refunds, and any paid tool or model usage. The 100-turn Pro case would require an explicit pilot subsidy. At low volume, staying within the Free mail quota is material to this price. If the real pilot needs Pro early or support time is high, revisit the rate or adopt a small monthly minimum before charging customers. Do not quietly recoup losses through surprise top-up fees. The current seven-day deletion applies to settled raw inbound MIME and output files; task records and text transcripts do **not** yet have a customer-facing expiry policy. Do not promise 30-day transcript retention until it is implemented and verified.

There is a provider-terms gate even with a single owner. OpenAI documents plan usage for open-source, locally hosted apps and directs paid or remotely hosted apps to an interest form; its commercial quickstart says selected private clients are eligible. TagMails' private repository, hosted relay, and proposed fee do not establish approval for customer Codex plan usage. Anthropic explicitly tells developers building a product for others to use API key authentication and prohibits routing third-party traffic against subscription limits. Its separate note that `claude -p` currently consumes subscription usage describes billing behavior, not permission for this product. Keep the live Claude subscription switch and customer Claude route on hold. Do not collect money or advertise a bring-your-plan beta until the relevant provider path is confirmed. ## Decision gate

Keep the five-cent debit in test mode. For a priced beta, measure at least: accepted turns and provider quota units per turn (including reactions), Worker CPU and D1/R2 use, file storage days, card fee by top-up size, retries, bounced replies, refunds, and human support time. Sample short and long multi-turn Codex tasks in the owner-only pilot. Resolve the provider-terms and text-retention gates above. Reconcile Stripe's signed test webhook, then validate the failure/refund policy against real delivery events before collecting real money. Only then approve or revise the proposed $0.15 service charge. A later managed API offer needs a separately measured maximum and margin.
